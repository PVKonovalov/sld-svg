# RELEASE.md

* 2026-08-19: Implemented the `svg-text` CLI (`extract`/`inject` subcommands) for translating text embedded in single-line-diagram SVG files — `data-name="..."` attributes and `<text>`/`<tspan>` content — using byte-exact XML scanning and patching so untranslated parts of a file are never altered.
* 2026-08-19: Added a per-SVG, semicolon-separated `key;source;translation` CSV translation-file format, keyed by a content hash so files can be freely reordered and re-extracted without losing existing translations.
* 2026-08-19: Added `--ru-en` (on `extract`) and `--filename-en` (on `inject`) flags providing a plain Cyrillic-to-Latin transliteration to pre-fill translations/filenames.
* 2026-08-19: Added `-dictionary` flag on `extract` plus a tracked `dictionary.csv` of common electrical units/abbreviations, to pre-fill exact, case-insensitive whole-string matches ahead of `--ru-en`.
* 2026-08-19: Added the `null` sentinel translation value (case-insensitive) meaning "delete this occurrence" (replace with an empty string), distinct from a blank translation ("not yet translated, leave untouched"); mapped the live-clock placeholder strings (`DD.MM.YYYY`, `DD:MM:YYYY HH:MM:SS`, and the typo'd `DD:MM:YYY HH:MM:SS` variant) in `dictionary.csv` to `null` so they're stripped from translated output automatically.
* 2026-08-19: Added `-rewrite` flag on `extract` to force-regenerate every translation from `-dictionary`/`--ru-en` instead of preserving whatever's already in an existing output `.csv` — needed because dictionary improvements couldn't otherwise reach files that were already fully filled by an earlier `--ru-en` run. Used it to regenerate all 144 `strings/*.csv` and `translated/*.svg` files against the current dictionary.
* 2026-08-19: Made dictionary matching whitespace-insensitive (spaces dropped entirely, not just collapsed, before comparing) so entries like `1СШ 10кВ` also match real source strings formatted with different spacing, e.g. `1 сш 10 кВ`. Regenerated `strings/*.csv` and `translated/*.svg` again to pick up the newly-matching entries.
* 2026-08-20: Added a new `internal/slddoc` package and `cmd/svg-sld` CLI (`extract`/`render` subcommands) that models a single-line diagram as a standalone XML document — placed elements with coordinates/orientation, drawn connectors, and an electrical topology (a node graph) reconstructed from the SVG's own geometry — separate from `svgtext`. `extract` covers a representative subset of xsde2svg's equipment catalog: busbars, generic wires (ошиновка/воздушная_линия/кабельная_линия/связь_с_объектом), junction points (точка), breakers (fixed and withdrawable), disconnectors, ground switches, and 2-winding power transformers; anything else is reported as skipped rather than silently dropped or guessed at. Element port geometry (where each symbol's electrical terminals are, before rotation) was derived directly from the corresponding `element_<code>.go` rendering function in the sibling `xsde2svg` source project, not reverse-engineered from rendered output. Topology is reconstructed by merging exact-coincident coordinates (wire endpoints, `точка` dots, resolved element ports) via union-find, with a small-tolerance snap pass for the few-pixel gaps some symbols' formulas leave, and by attaching anything that lies along a busbar's drawn length (not just its endpoints) to that busbar's single electrical node. `render` reads such an XML document back into a fresh SVG using a new tracked `symbols.xml` (one local-coordinate template per xsde2svg shape code, keyed separately from the semantic equipment class since two shapes, e.g. a fixed and a withdrawable breaker, can share a class) — it does not aim for byte-identical reproduction of the original SVG the way `svg-text inject` does, only a faithful new rendering. Also added a tracked `voltage-hints.csv` (hex color → real voltage-class name, e.g. `#962896;10кВ`) that `extract` uses to pre-fill each diagram's own `<voltageClasses>` table — voltage is modeled as this logical class name, not a raw color, with color kept only as that class's display style for rendering. Every element/connector/label also carries a mandatory `layer` reference (into a per-diagram `<layers>` table carried over from the SVG's `<metadata>`, plus an implicit always-present base layer), so a downstream viewer can show/hide by layer.
* 2026-08-20: Added a `## svg-sld` section to README.md documenting `extract`/`render` usage, an example diagram XML, and how `class`/`shape`/`voltage`/`layer` relate.
* 2026-08-20: Expanded `svg-sld extract`'s equipment coverage from 7 to 15 xsde2svg shapes, adding load-break switches (42), withdrawable disconnectors (49), ground terminals (31), choke coils (33), current transformers (34), surge arresters (35), fuses (203), and capacitors (388) — each verified against real instances from the example corpus, not guessed. Replaced the breaker/disconnector-specific port parsers with one generic `parseTwoPortDevice`, after finding that every one of these two-terminal shapes' true ports are always the pair of points furthest apart along the device's dominant axis across all of its path geometry, regardless of which shape-specific subpath convention produces them — a simpler and more robust rule than the per-shape "start point vs. end point" special-casing the original breaker/disconnector parsers used. Added minimal SVG arc (`A`/`a`) support to the path interpreter (endpoint tracking only) to support choke coils and current transformers, both of which draw their coil/loop geometry with arcs. Added corresponding `symbols.xml` render templates for all eight new shapes.
* 2026-08-20: Fixed the withdrawable breaker's (shape 43) `symbols.xml` render template, which had dropped a real path when first transcribed: the withdrawable "trolley" isolating contact is drawn as a short stub from the box plus a chevron on each side, with a small gap out to the fixed contact's own chevron — that gap is the isolating throw distance, by design, not a missing connector, but without the inner stub+chevron the render showed only the outer chevron floating with a large empty gap.
* 2026-08-20: Made the switch-like devices' (Breaker: 41/43; LoadBreakSwitch: 42; Disconnector: 71/162) internal state indicator actually reflect Element.State, instead of always drawing the same fixed line regardless of state: parallel to the device's own axis when closed, perpendicular when open (both confirmed against the xsde2svg source, which draws a vertical vs. horizontal line the same way for every one of these shapes), and diagonal (45°) for any other recorded value — a live-status convention supplied by the user that this static export format doesn't itself encode. Added a `{state:parallel|perpendicular|diagonal}` template placeholder in `symbols.xml` to select between the three per-shape variants at render time.
* 2026-08-21: Made `Diagram.Save` (`internal/slddoc/model.go`) emit self-closing tags (`<node .../>`) for attribute-only/empty elements instead of `encoding/xml`'s default `<node ...></node>`, via a post-processing regex pass over the encoded output — `Load` round-trips either form unchanged.
* 2026-08-22: Fixed `parseTwoPortDevice` (`internal/slddoc/elements.go`) ignoring a rotate() transform placed on an inner wrapping `<g>` around a two-port device's `<path>`s instead of on the element's own top-level tag — a pattern `PS_110kV_Valdai.svg` uses for rotated breakers (41) and disconnectors (162), e.g. element 1030 (`rotate(-90,2230,520)`), 2507, and 959, which were all extracting/rendering unrotated. Now searches the element and its descendants for the transform, not just the element itself.
* 2026-08-22: Added shape 106 (лампа/Lamp status indicator) to `svg-sld extract`/`render`. Verified against the xsde2svg source that shape 5 (initially proposed as "lamp") is actually `Текст`/plain text — this project's existing generic caption mechanism, already correctly routed to `Labels` — while shape 106 (`// element106 Лампа`) is the real lamp: a bare `<circle>` with no electrical port (real instances are never a wire's endpoint, so it's excluded from topology), whose `data-fill="0:off,1:on"` colors are read directly into new `Element.FillOff`/`FillOn` fields and picked between by `State` at render time, rather than reduced to the switch-like devices' fixed red/lawngreen/yellow state-indicator convention — since a lamp's colors are its entire appearance and carry real per-instance meaning. Added a `symbols.xml` template (a plain circle, `r="11"` matching the corpus's most common radius, `stroke:slategray` matching the source styling).
* 2026-08-22: Fixed the Lamp radius (previous entry) being hardcoded to `r="11"` in `symbols.xml` instead of read per instance — real corpus instances vary meaningfully, e.g. `PS_110kV_Valdai.svg` draws `r=11` "Индикатор" panel lights vs. `r=5` "АВ Валдай" lamps clustered in triplets next to a breaker. Added `Element.Radius` (from the circle's own `r` attribute) and a `{radius}` template placeholder so each instance renders at its real recorded size.
* 2026-08-22: Made `svg-sld render`'s output annotate each contiguous run of same-type elements/connectors with an English `<!-- Name -->` (elements: `<!-- Name:shape -->`) comment header, mirroring the source SVG's own `<!-- <russian_name>:<code> -->` convention (e.g. `<!-- разъединитель:162 -->` in `PS_110kV_Valdai.svg`) — translated, and keyed per-shape/per-connector-kind rather than per logical `Class`, since the source itself distinguishes shapes sharing one `Class` (e.g. a fixed vs. withdrawable breaker, both `ClassBreaker`, get separate headers "Breaker:41"/"Breaker (withdrawable):43").
* 2026-08-24: Added shape 320003 (ИКЗ/Fault Passage Indicator, "FPI") to `svg-sld extract`/`render`, a new `ClassFaultPassageIndicator`. Shape 320 is xsde2svg's generic "custom element" code covering several unrelated sub-variants keyed by `sde.InText` (direction arrows, pole lamps, ИКЗ, ...), of which only ИКЗ (rendered as `data-type="320003"`) is supported; real instances draw a `<g>` wrapping a fixed circle plus state-dependent decorative graphics (an "FPI" text label or arrow icons), so only the circle's position/radius are extracted, and — like the existing Lamp status indicator — it carries no electrical port and is excluded from topology. Its fill is rendered from the fixed `defaultBackground` constant rather than a `VoltageClass`, since every real instance draws the same dark fill regardless of state. Added the `symbols.xml` template (user-supplied, keyed `shape="320003"` to match the real `data-type`) and fixed its `<text>` element's blank `x`/`y` attributes to `"0"`/`"0"` so the "FPI" label actually centers on the circle.
* 2026-08-24: Fixed `svg-sld render` drawing every FaultPassageIndicator before the connectors, so a wire passing through one's position painted over and cut through its opaque circle. Unlike every other Element, a FaultPassageIndicator sits directly on top of a wire rather than only touching one at a port, so `Render` now defers it past the connectors loop instead of drawing it in document order — the wire is painted first, then the circle fully covers it, matching how the source SVG actually looks.
* 2026-08-24: Generalized the fix above into a proper Z-order setting (`elementZOrder` in `internal/slddoc/render.go`) instead of a single FaultPassageIndicator-only special case, and extended it to JunctionPoint (also drawn directly on top of a wire, same problem) and Lamp (a decorative status indicator meant to read as foreground UI). `Render` now buckets any Class with a nonzero entry into ascending tiers drawn after the connectors loop, so each still renders above every connector regardless of its position in the source document, while labels remain last (already on top of everything) and every other Class keeps rendering in ordinary document order, before connectors, as before.
